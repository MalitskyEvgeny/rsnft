# Прямая задача теплопереноса методом конечных объёмов

Проект читает исходные XLSX-файлы напрямую и решает температурную часть прямой
задачи в двумерном осадочном бассейне. Требуются `numpy`, `pandas`, `openpyxl` и
`Pillow`; SciPy и Matplotlib не нужны.

## Рекомендуемый адаптивный решатель

`adaptive_basin_fvm.py` строит динамическую quadtree-сетку. Ячейки рекурсивно
делятся около кровли и подошвы каждого слоя и в местах латеральной смены
литологии (контакты и разломы). После измельчения применяется 2:1-балансировка,
а потоки на гранях крупная–мелкая ячейка собираются консервативно.

Путь к `data1` уже задан по умолчанию, поэтому достаточно:

```powershell
python adaptive_basin_fvm.py
```

Более подробная настройка:

```powershell
python adaptive_basin_fvm.py --base-nx 8 --base-nz 16 --max-level 2 `
  --interface-band 0.55 --max-dt-ma 2.5 `
  --picard-iterations 8 --picard-tolerance-c 1e-3
```

`max-level=2` означает, что выбранная базовая ячейка может разделиться дважды:
на 4, затем каждая дочерняя ещё на 4. Для просмотра самой сетки:

```powershell
python visualize_adaptive_mesh.py adaptive_results\<run_id>
```

Наряду с обычным `result.npz` сохраняется `final_adaptive_mesh.npz` с точными
границами, уровнями, температурой, литологией и пористостью каждой адаптивной
ячейки.

`--picard-iterations` задаёт максимальное число нелинейных итераций на временном
шаге. В `metadata.json` для каждого шага сохраняется признак
`nonlinear_converged`; сводные поля `nonlinear_converged` и
`unconverged_time_steps` позволяют автоматически контролировать качество всего
расчёта.

## Серия адаптивных сеток и сравнение

Чтобы последовательно рассчитать уровни 1, 2 и 3 на базовой сетке 16×16,
построить изображения и сравнить решения с самой подробной сеткой:

```powershell
python run_adaptive_grid.py
```

Свои сетки задаются повторяющимся параметром `--case` в формате
`BASE_NX,BASE_NZ,MAX_LEVEL`:

```powershell
python run_adaptive_grid.py `
  --case 8,16,2 `
  --case 8,16,3 `
  --case 16,32,3
```

Готовая сводка создаётся в `adaptive_results\grid_comparison`: `README.md`
с таблицей и ссылками на изображения, `comparison.csv` для Excel и
`comparison.json` для последующей обработки. Уже рассчитанные варианты берутся
из кэша; параметр `--force` принудительно пересчитывает их.

## Что реализовано

- ячеечно-центрированный метод конечных объёмов на декартовой сетке;
- гармоническое усреднение теплопроводности на внутренних гранях;
- полностью неявная схема Эйлера;
- матрично-свободный метод сопряжённых градиентов с диагональным
  предобуславливателем (SciPy не требуется);
- итерации Пикара для формул Waples и Sekiguchi;
- верхнее условие Дирихле, нижний заданный тепловой поток, теплоизоляция боков;
- радиогенное тепловыделение;
- линейная интерполяция геометрии между эпохами;
- перенос температуры вместе с материалом слоя при деформации сетки;
- кэш входных таблиц и отдельный результат для каждой комбинации параметров.

## Визуализация сохранённого результата

```powershell
python visualize_results.py adaptive_results\<run_id> --age 0
```

В каждом каталоге расчёта находятся:

- `result.npz` — координаты, все 18 сохранённых эпох, температура, современная
  литология и пористость;
- `metadata.json` — параметры, время счёта, диапазон температур, диагностика
  нелинейных итераций и зафиксированные допущения;
- PNG-файлы, созданные визуализатором.

Общий `manifest.json` служит индексом всех комбинаций параметров.

Два результата можно сопоставить командой:

```powershell
python compare_runs.py adaptive_results\<coarse_id> adaptive_results\<fine_id> `
  --output comparison.json
```

## Зафиксированные допущения

В переданном комплекте отсутствуют заявленные в PDF `basin_data.py`, начальное
поле температуры, измерения и кинетические константы EASY%Ro. Поэтому начальная
температура задаётся линейным проводящим профилем по древнейшим поверхностной
температуре и базальному потоку. Свойства порового флюида приняты постоянными:
λ=0.60 Вт/(м·К), ρ=1000 кг/м³, c=4180 Дж/(кг·К); они доступны в
`AdaptiveConfig`.

Расчёт зрелости витринита намеренно не имитируется: для него нужны массивы
энергий активации, весов и предэкспоненциальных множителей EASY%Ro. После
получения этих данных модуль можно добавить поверх уже сохраняемой полной
температурной истории.
