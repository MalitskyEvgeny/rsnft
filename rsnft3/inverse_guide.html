Обратная задача rsnft3 — подробная инструкция

Восстановление базового теплового потока q(x, t) по наблюдениям температуры и отражательной способности витринита в скважинах. Ветка: dev-adaptive-only (актуально и для dev-inverse).

1. Физическая постановка и что мы ищем

Прямая задача — осадочный бассейн: стратиграфия из XLSX-фактуры (слои с границами top/bot и литологией на сетке возрастов 200–0 Ma), уплотнение (Sekiguchi), теплопроводность и теплоёмкость от литологии и пористости, стационарное на каждом подшаге уравнение теплопроводности (PCG), захоронение частиц и кинетика EASY%Ro (Аррениус: F = Σ fi(1−e−Ii), Ro = exp(−1.6 + 3.7 F) — исправленная формула (14)).

Неизвестный параметр θ — базовый тепловой поток q(x, t), дискретизованный по эпохам × X-узлам:

  • эпохи по умолчанию: 200–100, 100–35, 35–10, 10–0 Ma (4 эпохи, флаг --epochs);
  • X-узлы: границы профиля + средний узел --mid-x (23 400 м) при --n-nodes 3; q(x) внутри эпохи — кусочно-линейная по узлам;
  • итого dim(θ) = 4 × 3 = 12 значений мВт/м², бокс [30, 120];
  • индексация: (эпоха−1)×n_nodes + номер узла.

Наблюдения: T в точках скважин (TemperatureWellData.xlsx, σT = 2 °C) и Ro (VitriniteWellData.xlsx, σRo = 0.05). Цель — минимизировать

J(θ) = J_T + w_Ro·J_Ro + reg·J_reg
J_T  = Σ ((T_calc − T_obs)/σ_T)²        — невязки температуры
J_Ro = Σ ((Ro_calc − Ro_obs)/σ_Ro)²    — невязки отражательной способности
J_reg — штраф на негладкость q(x,t) между соседними узлами/эпохами

2. Как устроено вычисление (конвейер)

parameterized_data.jl   ThetaLayout, make_param_data: θ -> синтетический heat-Workbook
ro_kinetics.jl          EASY%Ro поверх прогона прямой задачи
observations.jl         WellPoint/WellSet: XLSX организаторов и twin-JSON
objective.jl            J(θ): прогон прямой задачи -> невязки в точках скважин (+кэш по θ)
criteria.jl             RMSE по скважинам, доли точек в σ/2σ, E^L2
invert.jl               DE (BlackBoxOptim) -> многоуровневая NM-полировка (по эпохам) -> ансамбль
run_inverse.jl          CLI-точка входа: <run_dir>/solution.json + result.npz
make_twin.jl            синтетические наблюдения из известного θ_true (проверка метода)
report_inverse.jl       самодостаточный HTML-отчёт по run_dir
adaptive_basin_fvm.jl   quadtree-решатель (эталонная синтетика, Ro-контроль, эксперименты)
Схема одной оценки J(θ): θ → синтетический heat-Workbook (q(x,t) на эпохах, эквивалент инжекции qbasal) → прогон прямой задачи на рабочей сетке (уплотнение + теплопроводность, PCG на каждом подшаге) → Ro-постпроцессинг → выборка расчётных T/Ro в точках скважин (билинейная интерполяция) → невязки. Оценки кэшируются по SHA-256 округлённого θ: одинаковые θ из разных стартов бесплатны.
Два бэкенда прямой задачи. :regular — равномерная сетка nx×nz (поиск и приёмка). :adaptive — quadtree: измельчение у границ слоёв/литологических переходов и вокруг точек наблюдений (well_spots); θ-независимая геометрия (меши, растеризации, состояния всех подшагов) предвычисляется один раз — precompute_adaptive_geometry, повторные оценки J идут по готовой геометрии.

3. Как запускать: сценарии

3.1 Полный рабочий цикл (рекомендуется)

# Этап A: DE-поиск на грубой сетке (быстро)
julia --project=rsnft3 -t 8 rsnft3/run_inverse.jl   --data-dir "Данные для обратной задачи"   --wells "Данные для обратной задачи/TemperatureWellData.xlsx;Данные для обратной задачи/VitriniteWellData.xlsx"   --grid 30,60 --ensemble 4 --workers 4 --de-budget 6000   --reg 0 --sigma-T 2 --sigma-Ro 0.05 --seed 11   --out results/inverse_stageA

# Этап B: NM-полировка на тонкой сетке с готового θ̂
julia --project=rsnft3 -t 8 rsnft3/run_inverse.jl   --data-dir "Данные для обратной задачи"   --wells "Данные для обратной задачи/TemperatureWellData.xlsx;Данные для обратной задачи/VitriniteWellData.xlsx"   --grid 60,120 --workers 1 --nm-iterations 40 --reg 0   --theta0-file results/inverse_stageA/solution.json   --out results/inverse_final

# Отчёт
julia --project=rsnft3 rsnft3/report_inverse.jl results/inverse_final
Правило иерархии сеток: поиск — на грубой (дёшево), приёмка — на тонкой (точно). --theta0-file переносит θ̂ между конфигурациями; смена сетки между этапами — осознанный контроль идентифицируемости.

3.2 Быстрая разведка (~2 минуты)

julia --project=rsnft3 -t 8 rsnft3/run_inverse.jl --data-dir "Данные для обратной задачи"   --wells "Данные для обратной задачи/TemperatureWellData.xlsx;Данные для обратной задачи/VitriniteWellData.xlsx"   --grid 20,40 --ensemble 1 --workers 1 --de-budget 2000 --nm-iterations 30   --max-dt-ma 5 --picard-iters 2 --pcg-tol 1e-4 --reg 0 --out results/probe

3.3 Twin-верификация (проверка метода — запускать до реальных данных)

# 1) синтетика с известным θ_true (75/80/85/90 мВт/м² по эпохам)
julia --project=rsnft3 -t 8 rsnft3/make_twin.jl --data-dir "Данные для обратной задачи"   --wells "Данные для обратной задачи/TemperatureWellData.xlsx"   --grid 30,60 --q 75,80,85,90 --sigma-T 2 --sigma-Ro 0.05 --seed 42   --out results/twin/twin.json
# 2) инверсия того же twin (reg=0 обязательно: J(θ_true)=0 только без регуляризации)
julia --project=rsnft3 -t 8 rsnft3/run_inverse.jl --data-dir "Данные для обратной задачи"   --wells results/twin/twin.json --grid 30,60 --ensemble 1 --workers 1   --de-budget 3000 --reg 0 --seed 1 --out results/twin_inv

Критерий успеха: J → ~Σ(шум/σ)²; средние θ̂ по эпохам ≈ θ_true (молодая эпоха — точнее всех); при ensemble>1 — таблица mean/std.

3.4 Адаптивная сетка

4. Результаты: файлы и их структура

solution.json — главный файл:
  • status, data_dir, wells_spec — что и на чём считалось;
  • grid: nx, nz, search_backend (regular|adaptive);
  • layout: имена параметров, nodes_x, эпохи, бокс lower/upper;
  • settings: все CLI-настройки запуска;
  • observations: сводка по скважинам (сколько T/Ro точек вошло);
  • n_dropped_T_inactive: точки, отброшенные вне активной области;
  • ensemble[i]: theta, J, J_T, J_Ro, J_reg, de_evals, nm_evals, elapsed_s, seed каждого старта;
  • best: theta (12 значений) и breakdown J лучшего старта;
  • criteria: rmse_T, rmse_Ro, frac_1s_T, frac_2s_T, frac_1s_Ro, frac_2s_Ro, l2, per_well[];
  • adaptive (при --adaptive-final): критерии на адаптивной сетке;
  • elapsed_total_s.
result.npz — поля финального прогона:
  • x, z — координатные сетки, м;
  • ages_ma — сохранённые возрастные срезы;
  • temperature_c — (время, z, x), °C;
  • final_lithology, final_porosity — финальный срез;
  • final_surface_m, final_base_m — дно и кровля фундамента.
result_adaptive.npz + mesh_adaptive.png — то же для адаптивного этапа.

cache_main/ — кэш оценок J (можно удалять).
report.html — отчёт (report_inverse.jl).

5. Как интерпретировать критерии

МетрикаСмыслХорошее значение
rmse_TRMS невязок T по всем точкам≤ 2σ_T = 4 °C; отлично ≈ σ_T = 2
rmse_RoRMS невязок Ro≤ 2σ_Ro = 0.10
frac_2s_Tдоля T-точек с |res| ≤ 2σ≥ 95% — приёмка (условие 18)
frac_1s_Tдоля точек в σ≥ 60–70% на реальных данных
l2 (E^L2)расхождение с эталонным прогоном (только twin)→ 0
  1. Приёмка (условие 18): RMSE ≤ 2σ И ≥ 95% точек в 2σ. Если RMSE_T ≈>r; σ_T — модель не объясняет температуру; смотреть, где сидит невязка: верх профиля → Tsurf/свойства пород, низ → q (наш параметр).
  2. Идентификация θ̂: std по ансамблю ≪≪ ширины бокса [30,120] — параметр выявлен; std ≈ полбокса — неединственность. Ro интегрирует всю тепловую историю: старые эпохи (200–100, 100–35 Ma) ограничены слабее всего — разброс ожидаем именно там.
  3. Эквифинальность: средние по эпохам могут обмениваться смещением (компенсация между соседними эпохами) при близком J — смотрите per-epoch средние θ̂, а не только компоненты.
  4. J_reg: большой скачок от гладкого приора = данные требуют латеральной изменчивости q(x) — проверить x-узловые столбцы θ̂.
  5. Устойчивость минимума: независимые старты DE сходятся к J_min с разбросом < 0.1% — сначала сравните J между стартами, и только потом интерпретируйте разброс θ̂ как физику.
  6. Контроль сетки: приёмка на рабочей сетке; лучший θ̂ дополнительно прогоняется на сетке ×1.5 или адаптивной (--adaptive-final). Систематический сдвиг критериев при смене сетки = смена модели.

Отрисовка — порт rsnft2/visualize_adaptive_mesh.py: заливка ячеек температурой (палитра magma), обводка цветом уровня измельчения (серый L0, синий L1, красный L2, фиолетовый L3), серая заливка — неактивный фундамент; PNG 1500×900 пишется напрямую, без внешних зависимостей.

6.3 Картинка для конкретного θ̂ обратной задачи (например, из E4)

using JSON
include("rsnft3/objective.jl")
data  = load_dataset("Данные для обратной задачи", "results/_ageprobe")
wells = load_wells_xlsx("Данные для обратной задачи/TemperatureWellData.xlsx",
                        data; kind=:T, sigma_T=2.0)
acfg  = AdaptiveConfig(base_nx=30, base_nz=60, max_level=3, max_dt_ma=2.5,
                       picard_iterations=3, picard_tolerance_c=1e-3,
                       linear_tolerance=1e-6, preview_nx=120, preview_nz=160,
                       well_spots=[(p.x, p.z) for p in wells.points])

# th_layout — ThetaLayout с теми же epochs/n_nodes, что в E4
res   = run_adaptive(data, acfg; qbasal_by_age=qbasal_by_age(th_layout, th, axg, data.ages),

save_mesh_drawing(res.mesh, res.grid, res.final_temperature_cells,

Главный рычаг — --pcg-tol 1e-4 на этапе поиска (ландшафт J сохраняется до 5–6 значащих цифр, минимум не меняется). «Золотое правило»: быстрые ручки — для поиска, финальные критерии — всегда точным решателем из θ̂ через --theta0-file. Воркеры окупаются при ≥ 0.15 с/оценку; на 20×40 — --workers 1.

8. Адаптивная сетка: когда применять (измеренные выводы)

  1. Эквивалентность level-0: при max_level=0 адаптивный решатель совпадает с равномерным до дискретизации граней (RMS 0.0044 °C, отн. 2×10−5).
  2. RMSE_T ограничен разрешением интерьера базы: b16×32 L2/L3 → 3.58/3.44, b32×64 → 3.37; равномерная 60×120 даёт 1.53. Измельчение у границ слоёв не помогает T-точкам в интерьере — ошибка приходит через грубый стенсил окрестности; пятна вокруг скважин (well_spots) дают лишь ~0.1 °C.
  3. RMSE_Ro адаптив улучшает стабильно: 0.027–0.035 → 0.018 (частицы Ro сидят на границах слоёв, где измельчение работает).
  4. Twin-приёмка (эталон адаптивный, base 30×60 L1, θ_true = 75/80/85/90): инверсия 20×40 — RMSE_T 4.21; адаптивный контроль от recovered θ̂ — 0.53 °C; молодая эпоха 89.65 (−0.35 мВт/м² от истины, окно 90±3 выполнено).
  5. Замороженный меш (--adaptive-frozen): при b16×32 результат побайтно совпадает с подвижным; при b30×60 дестабилизирует remap (экспериментальный режим, по умолчанию выключен).
  6. Практическое правило: T-этап контроля — равномерная полировка (--theta0-file на 60×120); адаптив — Ro-критерий и эталонная twin-синтетика.

9. Грабли

Регуляризация и twin: twin-проверка — только с --reg 0, иначе J(θ_true) ≠ 0 строго.
  • Глубина в XLSX организаторов положительна вниз; загрузчики это учитывают. У скважины A 2 точки вне осадочной геометрии — отбрасываются при загрузке (видно в solution.json).
  • --nm-iterations — итерации симплекса, а не оценки J (реальное число оценок в 10–15 раз больше). Быстрая полировка: 30–40 итераций.
  • Первый запуск после addprocs платит за JIT каждого воркера (~20–30 с) — бюджет оценок считать для steady state.
  • При --sigma-T 0 (точный twin) доли «в σ» в отчёте = null — ожидаемо.
  • Julia запускать с -t 8; DE параллелится по воркерам, NM — строго последователен.
  • Кэш J ключуется по θ (SHA-256 округлённого вектора) — одинаковые θ из разных стартов бесплатны; каталог кэша можно удалять целиком.
  • Артефактные точки (вне активной области / вырожденный стенсил на тонком клине) исключаются из J с вкладом 0 и считаются в n_artifact_T/Ro (solution.json); при n_artifact > 0 приёмка строгая — passed=false, не сбой оптимизации.
  • results/ в .gitignore — выводы фиксируются пустыми коммитами; генерируемые файлы помечаются как производные.
